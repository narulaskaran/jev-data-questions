# Jev Data Analysis

This repository is the **Jev data analysis** product (originally Jev Gamecast). Live ESPN gamecast is historical implementation material only.

## Read first

- `PLAN.md` — product pivot, MVP scope, contracts, stages, and remaining gates
- `docs/analysis-api.md` — analysis + BYOD dataset API contract
- `README.md` — install, test, and Convex/Vercel/UploadThing notes

## Product

Bring a dataset. Open a dashboard of 2–4 insights. Jev fills the values.

Audience: people who want a chart from their data. Jev stays invisible on the happy path. Chart type follows data shape (categorical / numeric / time / geo / cardinality), not a fixed Choice-bars vs Noul-line pairing.

## Current slice

- **Idle:** title **Dynamic insights from your data.** plus Bring your own (CSV upload or public HTTPS CSV URL). No sample demo buttons, JSON editor, Draft task, or chart until a dataset is opened. Title stays; do not collapse into a blank poster. Still no limits/about essays. Fixture CSVs for BYOD QA live at `public/samples/seahawks-super-bowl-2026.csv` and `public/samples/nyc-squirrel-census.csv` (served as `/samples/…`).
- **Dataset page:** BYOD (or a known `/dataset/:id` fixture URL) goes to `/dataset/:id`. A dedicated dashboard is the product surface: 2–4 tiles start in parallel and paint as each completes (skeletons OK while filling). Chart types on one page must be **diverse** (map + series, or series + bars) — fail if every tile is the same viz kind. Landing is BYOD only; InsightPicker → single Run is not the door. Draft / Edit Jev JSON / Run Jev stay on Engineer (`?mode=engineer`).
- **Shape:** a quiet schema strip sits above the dashboard with human type labels (Places · Numbers · Text); the dataset preview table stays below the tiles and is secondary (collapsible, max-height scroll — especially at 390px).
- **Insights:** on BYOD entry the server LLM proposes 2–4 named insights (`title` / `question` / `visual` / `perspective` / `preparation` / `reason`). Proposals are validated and sanitized; raw-column junk (AM/PM, shift, “Labels in this table”) is dropped. The viz pack picks the chart. Omit leftover garbage rather than filling tiles. Fixture-shaped uploads still use the Seahawks SEA win + play quality pair and the squirrel eating map + ranked-eating bars (never P(moving) over sighting index). Tiles start in parallel; if proposals fail, the dashboard stays honestly empty.
- **Idle copy:** one upload phrase — **Upload CSV** — plus a public HTTPS CSV URL. Large URL fetches show loading progress (indeterminate bar, then Still working…). Dashboard tiles show progress % from 0 while a run is in flight.
- **Advanced:** Draft task / Edit Jev JSON / Run Jev stay off the default URL. Open `?mode=engineer` or the footer **Engineer** link to edit pretty-printed Noul / Choice / Score JSON. Choice still shows class chips above the JSON. Run Jev is enabled when that JSON is valid. Invalid JSON disables Run.
- **Run:** the proposed viz is the hero. `Row X of Y` rail only if the viz is row-streamed (series/bars; not places). Percent chrome stays (`completedRows/totalRows`, snaps to 100% on complete). Chart and rail accept out-of-order completions sorted by `rowIndex`. Completed runs can download a formula-escaped results CSV. Share remains a header button that copies the public URL. Mid-run failures use plain-language copy plus resume from the last good row — never raw internal codes. A live run with no progress for ~60s shows **Still working…**, then **This run may be stuck — Resume or start again** after a lease-dead heal. Never plot CSV `wpa` as if Jev produced it.
- Samples: Seahawks win likelihood per play (Jev Noul, live P(win) line) over **full-game** SEA plays with absolute score state. Seahawks play quality / grading is a Score series over the same **71** plays, not Good/Bad Choice on the H1 39-play slice. Squirrel census is a slim checked-in Central Park–shaped fixture (lat/lng, location, eating). Choice classifiers keep class-distribution bars when that is the insight; the football H1-only yards-evaluation slice still says so (`Classifying 39 of 71 rows (H1 plays).` / `Classified 39 of 71 rows (H1 plays).`) only for explicit player/yards classification (K.Walker / C.Kupp / etc.). Football is a sample, not the product.
- UI: Tailwind CSS + shadcn-style primitives (zinc neutrals; indigo only for Run / Run Jev and the live chart accent). Motion guides the flow (~300ms ease-out; reduced-motion snaps). Keep the chrome quiet. Production injects `@vercel/analytics` from the Vite entry so Vercel Web Analytics tracks jev-gamecast.vercel.app.
- Dataset preview shows the full accepted table (football 71×26; squirrel slim fixture; BYOD all accepted rows × all columns) in a max-height ~280px scroll box with overflow-x and overflow-y. Large tables virtualize visible rows so the main thread stays responsive; scrolling still reaches every accepted row and column. No first-N truncation caption. At 390px, table scroll stays inside the card; page width stays ≤ viewport. QA this locally with `npm install && npm run dev` — do not wait on a Production deploy.
- Server routes under `api/analysis/*`, `api/datasets/*`, `api/share/*`, and `api/browse`. Drafting uses OpenRouter except a durable cache hit for the same dataset + normalized task (sample Super Bowl win-likelihood and squirrel where-they-eat are also in-code short-circuits). When `datasetId`/`fixtureId` is known, draft and complete-run lookups run before loading the fixture or BYOD table. Failed drafts are not stored. Draft cache write failures are logged and flagged (`cacheWrite: skipped`); they do not fail the draft. Only run may call Jev. The run worker classifies with a bounded Jev pool (concurrency 6, max 8) and pipelines Convex snapshot puts so the next classify is not blocked on the previous write. Convex upserts only new result rows per put. A lease-dead queued/running snapshot with no progress for ~60s is healed to a retryable error on poll/share so Resume works. Same-owner analysis leases stay exclusive. **Same dataset + same Jev query always reuses a complete snapshot** (sample fixture and BYOD). Lookup key is `datasetId` (fixture id when that is the dataset) + canonical query + question kind + classes. A second run does not call Jev or mint another analysis. In-flight queued/running snapshots for that content key are joined rather than duplicated. `forceNew: true` is the only escape hatch. The playground never sends `forceNew`; a `complete` start stays a saved run and snaps to 100% without extra chrome.
- UploadThing stores original CSV blobs; Convex stores dataset metadata, immutable row refs, run progress, and incremental predictions.
- Production fails closed without `CONVEX_URL` (or the Convex Vite alias `VITE_CONVEX_URL`) + `CONVEX_WRITE_SECRET`. BYOD upload/URL also fails closed without `UPLOADTHING_TOKEN` (or `UPLOADTHING_SECRET`). Use the UploadThing dashboard **API Keys → V7** token (base64 JSON `{ apiKey, appId, regions }`). A raw `sk_…` key is not enough to upload: v6 `uploadFiles` is retired (`Unsupported operation`). Missing app id/region returns `UPLOADTHING_FAILED` with `failure: "TOKEN_MISSING_APP_REGION"`. Convex dataset persist (`datasets.put`) omits undefined optional fields and client-only keys before `authorizedPutDataset`; Convex failures return `DATASET_INTAKE_UNAVAILABLE` with `failure: "CONVEX_PUT_FAILED"` and a secret-free reason — not `UNCAUGHT`. **Vercel Production builds must run `npx convex deploy`** (`node scripts/vercel-build.mjs` via `vercel.json` `buildCommand`) with `CONVEX_DEPLOY_KEY`. A frontend-only `npm run build` leaves Convex on stale functions and BYOD fails with Convex HTTP `Server Error`. Sample on-ramp does not need UploadThing.
- Historical Gamecast forecast/ESPN cron code still exists under `historical/api` and `src/server` forecast/ESPN modules. Those routes are not shipped as Vercel functions. Do not treat them as the active product surface.

## Boundaries

The browser must never import or call Jev, OpenRouter, ESPN, TypeSafe SDK internals, UploadThing server tokens, or privileged Convex writes. Secrets stay in server runtime env (`JEV_API_KEY`, `OPENROUTER_KEY`, `CONVEX_WRITE_SECRET`, `CONVEX_DEPLOY_KEY`, `UPLOADTHING_TOKEN`, `CRON_SECRET`). Tests and replay must not make paid provider calls. Visiting or sharing a page must never start a Jev run.

## How to continue

Implement against `PLAN.md` from the existing workbench. Remaining work is pause/cancel, browse/share completeness, abuse/cost controls, provider-contract confirmation, and Stage 6 operator provisioning. Do not restart from the old live-ESPN plan.
